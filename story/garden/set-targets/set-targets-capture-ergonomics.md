# Set-targets = Capture ergonomics, learned through using the app

**Thesis (writer's reframe).** Not "we fixed a text field" and not "we bemoan a refactor" — the input
design is shaped by the friction an athlete actually hits mid-session. It's the least glamorous but
most **load-bearing** surface: logging is the input the whole Capture → Compare → Communicate chain
runs on, so if setting a target is annoying, everything downstream starves. Low friction to log *is*
the product.

This piece is the app's **Capture-side counterexample** to the other three reports (which are all about
*reading* — Compare/Communicate). It doesn't share the "legible at a glance" spine; it shares the
**design-values** layer ([[honest-representation]]): derive-don't-store, control over speed, root-cause
over band-aid.
